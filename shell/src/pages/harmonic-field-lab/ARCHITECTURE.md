## Contracts

### Pitch

- A note is `{ m, c }`: `m` an exact monzo `{ prime: exponent }` (prime keys are decimal strings) or `null` for an
  irrational pitch (EDO steps, typed cents); `c` its cents above the root. Products of an irrational and a rational note
  are irrational. Decision H-1 (`shell/DECISIONS.md`): the lab stores monzo + cents only. Midicents or Hz are derived from
  `c` at an edge (audio, a Workbench handoff, consistent with W-1) and never stored in place of the monzo.
- A field is `Note[]` reduced into `[0, repeat)`, prime-filtered, sorted by cents, de-duplicated within 1e-6 cents (a
  rational note wins over an irrational one), capped at 2048 (`MAXN`).
- A subset is a set of field indices plus a mode (which selected note is the root); `rotateSubset` turns it into a
  `RelNote[]` (notes above the mode root, each with `src` = its field index). Analysis functions take that.
- Tolerances: "same size" is strictly less than 0.01 cents (`tol`); the chord finder's musical tolerance `tolC` is
  inclusive and defaults to 18 cents in the UI; `transpositions` falls back to cents with `tolC` inclusive (default 0.01).
  Test comparisons use 1e-3 cents unless a handler says 0.01. Full rules: `src/lib/harmonic-field/README.md`.

### Module map of the lib

See the table in `src/lib/harmonic-field/README.md`. In short: `intervals` (monzo, note, text parsing, prime filter),
`generators` (harmonic, EDO, box lattice, diamond, CPS, custom), `field` (`buildField`, lattice, CPS chords), `subset`
(rotate, carry selection, nearest ED, odd limit), `shape` (step sizes, MOS, interval spectrum, propriety, constant
structure), `chords` (templates, finder, closest, ladder), `chordLibrary` + the generated `chordLibraryData` (M7: Scala's chord list, merged, grouped, filtered, added to the templates), `scales` (melakarta, Western library, nearest scale pick),
`keys` (transposition map), `deviation` (nearest ratio, targets, "vs JI"), `scala`, `presets`, the scorers and `retuner`, `visual` (lattice, EDO fit, dissonance curve, iso grid), `library` (generator identity, subsets as pitches, Update report), `sketch` (chord sketch and shapes), `composite` (merging), `positional` (step-pattern chords), `liveRoughness`, `shapeGroups`, `harmonicEntropy` (M9: the HE curve, exact values, Fixed range). ### Lab state shape

```ts

  tabs: Tab[]; active: number; nextTab: number;        // up to 12 tabs
  library: GenLibrary;                                 // user presets, Untitled generators, subsets (as pitches), recents
  notice: Notice | null;                               // after Update / Save-as-new copy: report + undo (runtime only)
  refusal: { reason } | null;                          // a library action was refused (a cap, an unbuildable generator)
  lastLoad: { id, found, missing } | null;             // the last subset/load: how many pitches the field had (runtime only)
  lastAdded: { id, duplicate } | null;                 // the row Add made or found (runtime only)
  forkNote: { owner, reason } | null;                  // subset/add forked into an Auto-saved generator (runtime only)
  hover, pin: number | null;                           // field index pointed at / pinned (inspector)
  chordHover, chordPick: Set<number> | null;           // highlighted chord (a hovered chip, a clicked chip)
  chordHoverPitches: number[] | null;                  // the hovered chord's real pitches when its card carries them
  preview: number[] | null;                            // saved subset pointed at (shown instead of the selection)
  sounding: Set<number>;                               // field indices that sound now (every view lights them)
  soundingMarks: Set<number>;                          // strip marks lit alone (a strip target that is no field note)
  soundingGhosts: number[];                            // cents of sounding pitches that match no field note
  soundingPitches: { c, src }[];                       // every sounding pitch as played, and the field note it lights (-1 none)
  soundingChords: string[];                            // shelf chord ids that sound now (their cards light)
  ui: UiSettings;                                      // panel, dock, tolerance, ring, visualizers, sound, keys, folds
  layout: Layout;                                      // pinned columns
  templates: ChordTemplate[];                          // chord finder templates
  templateNote: { text, refused } | null;              // M7: outcome of the last templates/addLibrary (runtime only)
  patterns: PatternsState;                             // positional chord patterns (state/patterns.ts)
  retuner: RetState;                                   // cards, settings, the run (state/retuner.ts)
  shelf: ShelfState;                                   // stashed chords, selection, sketch row (state/chordShelf.ts)
  composites: CompositesState;                         // up to nine composite gamuts (state/composites.ts)
  keys: { shift, page, link };                         // runtime: melody shift, shelf page, linked chord id (M8b)
}
Tab { id, name | null, gen: GenSpec, field: Note[], rep: Note, err, sel: number[], mode,
      lastMethod, cmp: {ref, odd, m}, pick: {scale, kind, stretch, m, ref, msg, ok} }
Tab also has `link?: OwnerKey` (the generator it is linked to, stored in tabs.v1 beside the snapshot), `fromChord?` (the shelf chord it was reloaded from, stored as `from`) and `pending?` (the stored selection of a tab whose inputs did not build).
Saved { id, name, gen: GenSpec, selCents: number[], mode }   // legacy subsets.v1 entry only
```

- `field`, `rep` and `err` are built by `generateField(gen)` inside the reducer (so the selection can be carried across a
  regeneration with `carrySelection`) and are never stored. A failed build keeps the old field and shows `err` inline.
- `sel` is a sorted list of field indices; `mode` indexes `sel`. Changing the field clears hover, pin, chord, preview and
  sounding (they point into the old field). Switching tab does the same.
- Everything derived (`deriveBase`, the strip, the analyses) is `useMemo` per active tab in `LabProvider`; there is no
  module-scope mutable state or cache tied to lab data (the one module-level value is the WebGL capability probe, `components/webgl.ts`).
- Clicking a note anywhere (ring, strip, 2D and 3D lattice, iso keyboard, dissonance marks, compact and full field table)
  calls `clickNote`: it toggles the note in the subset and does not pin. **Alt+click** (Alt+Enter on a focused note) calls
  `pinNote` (action `pin/toggle`): it pins or unpins the note in the inspector and does not toggle it. Views build their
  handlers with `noteHandlers(lab, i)` in `components/ui.tsx` (the 3D lattice passes `altKey` through `onPick(i, alt)`).
  A pinned note is `--mark-yellow` in every view (DECISIONS H-3): `pinRing` on the ring and 2D lattice, a yellow halo in 3D,
  `markPin` on the strip, `data-pin` outlines on iso hexagons, dissonance marks and field-table rows. Hover keeps the `--text`
  `selRing`. The full table's checkbox still toggles.
- The ring draws the selected subset as its own polygon (`subsetFill`, `--text`-based, notes in ring order, in both Chromatic
  and Fifths views) under the blue chord polygon.
- Lattice axes: `rankAxes3d` (lib) scores every three-prime choice by how many selected notes sit on the grid with no stem.
  The picker lists them best first with the count (`3·5·7 — 7/7 on grid`) under an **Auto** entry; `VizSettings.axes3 = null`
  is Auto and follows the best fit as the subset changes, a picked triple stays until Auto is chosen again (a stored triple the
  field no longer offers behaves as Auto). The rail summary shows the effective axes.
- Nearest scale menu: next to `m-ED` it has an **Odd limit...** entry (`PICK_ODD`); `Tab.pick.odd` holds the number (stored as the
  optional `pickOdd`, default 15, clamped 1..255), the one Select button applies it. All / None / Invert are one joined button
  row (actions); SegmentedControl stays for two-state choices.
- Key rings (Keys & Modes) are buttons: a complete ring makes that key the subset with its root as the mode root, Ctrl/Cmd-click
  plays its notes together; heat-grid rows set the current mode.
- Subset rows of the current generator: the list shows the subsets owned by the tab's generator (`Lab.owner`), re-resolved against the
  tab's field; "All" lists the rest (loading one switches the tab to its generator). See "Generator library" below.

### Generator library (M7b, step 1: data layer)

A generator is a named preset that OWNS its subsets. An owner is an `OwnerKey`: `b:<built-in preset name>` (the preset's data stays in the
lib's `PRESETS`; only its subsets are stored), `p:<id>` (a user preset `{ id, name, folder, gen }`, folder a plain string `"A/B"`),
`u:<id>` (an Untitled generator `{ id, gen }`: a generator that got a subset before it was named). All subsets live in one flat list
`{ id, owner, name, pitches: Note[], root: Note | null }`: PITCHES (monzo + cents; the mode root as a pitch too), never field positions.

- Identity: `genKey` = lib `generatorKey`: exactly the inputs that decide the field (method, repeat by pitch, prime mask, plus the method's own
  inputs; not the preset label, `keepNew` or the inputs of other methods).
- A tab's generator (`ownerOfTab`): its `link` when that still exists; else the built-in named by `gen.preset`; else a user preset, an Untitled
  generator or a built-in with the same `genKey`; else none. `isModified` = linked but `genKey(tab.gen)` differs from the owner's (the dot).
  Fork on edit: a `gen/*` edit never touches the library; the tab is just modified.
- Resolution: `resolvePitches` (exact monzo, else the nearest note within 0.5 c); a subset re-resolves against the tab's field whenever a row is shown or loaded.
- Add (`subset/add`): current selection to the owner's next row, label `Subset N` (first free), no name needed; an identical pitch set and mode
  root returns the existing row (`lastAdded.duplicate`). No cap. An unsaved or modified tab first forks into an Untitled generator with the tab's
  inputs (an existing one with the same inputs is reused) and links to it, so a subset is never orphaned and a preset is never changed.
- Update preset (`preset/update`; user presets and Untitled only, never built-ins): the owner takes the tab's inputs, every subset re-resolves,
  unmatched pitches and then-empty subsets are removed; `state.notice` carries the `UpdateReport` (`updatedSubsets`, `removedSubsets` + `removed`,
  `affectedSubsets`, `affectedAverageLost`, `mostLost`, `pitchesFound/pitchesTotal`, `detail` per affected subset with kept and lost pitches for
  Show removed) and the undo data. `notice/undo` is defensive: it touches only what the Update changed (the subsets it rewrote or removed, by
  id, plus the generator): a rewritten subset comes back only if it still is what the Update left (one renamed, changed or deleted since is left
  alone), a removed one comes back at its old position, the generator returns only if it still is what the Update set, and no other subset is ever
  touched or removed. The notice also ends at the next generator edit, any tab action except `tab/link`, `subset/add|rename|delete`, `lib/sync`,
  `preset/save|rename|move|delete`, or `notice/dismiss` (a copy notice made by `preset/save` itself stays).
  `updateBlocker(lib, tab)` returns the reason Update would do nothing (no generator yet, built-in owner, nothing modified, unbuildable inputs,
  no notes) or null; `Lab.updateBlocker` and `Lab.canUpdate` expose it so the button can be disabled with the reason. The reducer still no-ops safely.
- Save as new (`preset/save {name, folder, copySubsets?}`): a new user preset from the tab's inputs, tab linked; plain = no subsets, `copySubsets` =
  the owner's subsets re-resolved against the tab's field under new ids (notice kind `copy`, no undo). Naming an unmodified Untitled generator
  promotes it instead (its subsets move). Also `preset/rename`, `preset/move`, `preset/delete` (subsets are KEPT under an Untitled generator with the
  preset's inputs; tabs that linked to it relink), `preset/open {owner}` (builds the generator in the tab, links, Recent), `tab/link`, `recent/push`.
  Recent = last 8 owners used (open, save, add, load).
- Refusals: `addSubset`, `saveUserPreset`, `ensureUntitled` and `copySubsetsTo` refuse (no change, a `refused` reason) at the caps below; the
  reducer then sets `state.refusal = { reason }` (cleared by the next `subset/*`, `preset/*` or `lib/sync` action). `preset/save` with
  `copySubsets` builds `generateField(tab.gen)` itself (the tab's field is stale after a failed edit) and refuses when it does not build.
  `preset/delete` is refused when its subsets would have nowhere to go (Untitled cap).
- Orphaned subsets (owner gone, e.g. a built-in renamed in a later version) stay stored and are written back; `orphanSubsets(lib)` lists them and
  `subset/load` applies one to the CURRENT tab from its own pitches (tab link unchanged); `state.lastLoad = { id, found, missing }` says how many
  pitches the field lacked.
- Caps (equal in memory and at load, so a reload never drops what a session accepted): 2000 presets, 2000 Untitled generators, 20000 subsets,
  4096 pitches per subset.
- Known data-loss rules for corrupt or future data (load drops them; the first save then writes the library without them): a subset whose owner
  key is syntactically invalid (not `b:`/`p:`/`u:` plus text) is dropped; an entry that is not an object, a preset or Untitled entry without a
  usable generator, and a pitch without finite cents are dropped; a monzo that is not plain (non-prime key, non-integer exponent) loses its
  monzo and keeps its cents; a root that is not one of the subset's pitches is repaired to none. A stored preset or Untitled generator with an
  unknown future method or preset name is changed to the defaults (not kept as stored); with duplicate preset or Untitled ids the second
  entry gets a new id, so its subsets end up under the first. Well-formed entries that cannot be used now (owner gone) are kept.
- Legacy `subsets.v1` entries written after `generators.v1` exists (for example by a tab still running an older build) are never migrated:
  they stay on disk, untouched, and are not shown.
- A later Import reuses `applyUpdate` / `copySubsetsTo` unchanged (they take any subsets and any field).

Migration of the legacy `subsets.v1`: at load, when `generators.v1` is absent or unreadable, the flat list is converted in memory (`migrateSubsets`;
nothing is written, so it is idempotent, and `subsets.v1` is never touched or deleted): entries are grouped by `genKey`; a group equal to a
built-in preset's inputs is owned by that preset (the one the entries name, else the first), every other group becomes an Untitled generator; pitches
come from each `selCents` looked up in the field the entry's generator builds (exact monzo when a note is within 0.01 c, else cents only; a generator
that does not build gives cents-only pitches), the root is the pitch at the stored mode (the first when out of range). Every entry appears with its id
and name. The first library change writes `generators.v1`, which is then authoritative.

### Chord shelf (M8a: step 1 data layer, step 2 UI below)

`LabState.shelf: ShelfState` holds the stashed chords, the selection, the sketch row and two runtime notes. Everything is plain data (a later Workbench
hand-off can read `chordshelf.v1`; W-1: midicents only at the hand-off).

- A chord (`ShelfChord`): `id` (`c<N>`, never reused), `name`, `pitches` (the EXACT pitches heard, monzo + cents, root first, in the order played; for a
  sketch chord `sketchPitches(root, template)` stacks the template's integer ratio on the root, not reduced into the repeat), and provenance:
  `template` (text or null), `rootDeg` (the root's degree in the source subset read from its mode root, null when unknown), `tol` (the chord finder
  tolerance), `date` (ISO, passed in by the caller), `refHz` and `frame` (`parallel` | `relative`: the reference frame at stash time), `parent` (the shelf
  chord whose reloaded tab it was stashed from, lineage; a deleted parent leaves a dangling id on purpose, ids are never reused), and `source`
  (`{ gen, tab, subset: { pitches, root } }`: the tab's generation inputs as in `generators.v1`, its name, and its subset as pitches; null when the
  tab had no selection or the stored source was unusable: the chord still plays but cannot be reloaded).
- Pitch frame rule (human decision 2026-11-14, chord frame changed 2026-11-15): `pitches` are FIELD-ABSOLUTE, the field's own pitches above 1/1, identical whether
  stashed in Parallel or Relative (`frame` only records the switch). For CHORDS the Parallel | Relative switch (key 0) is `chordPitchesFor(chord, frame)`:
  Relative plays them as stored; Parallel divides each by the chord's OWN root (`pitches[0]`, root first), so every chord starts on 1/1 (parallel major / minor).
  Example, 12-EDO with mode root C: C major (0, 400, 700 c) and E minor (400, 700, 1100 c); Relative plays those, Parallel plays 0, 400, 700 and 0, 300, 700.
  The same rule applies to the shelf slot (click, hold 1, Play selected), the chord keys, the chord chips (`chordPlan(field, members, p, rootIdx)`,
  `playFieldChord(idx, rootIdx)`) and Play sketch (`abs[0]` on 1/1). It does NOT apply to hold 4 / hold 5 (the pointed note is the root; they keep
  `framedCents(p, c)` in `plan.ts`: `modeAtBase ? c - rootC : c`, the mode-root rule; the plan's `modeAtBase` flag is `ui.modePlayback !== 'relative'`), nor to mode previews, Play scale, Play chord on a highlighted chord (no root
  known: mode-root rule) and the computer melody keys, which keep the mode-root rule. The linked melody has its own frame (below).
  Lights always land on the stored field-absolute pitch in both frames (H-2): `pitchesPlan(..., light)`.
- Actions: `shelf/stash { stash: StashRequest }` (the UI supplies the pitches, template, rootDeg, optional name and the date; tolerance, 1/1 Hz, frame,
  generator, subset, tab name and parent are read from the active tab and `ui` by the reducer), `shelf/rename`, `shelf/move { id, to }` (clamped),
  `shelf/delete`, `shelf/select { id, additive? }` (plain: only this slot, again clears; additive: toggle), `shelf/selectAll`, `shelf/selectNone`,
  `shelf/sync` (another window saved), `shelf/reload { id }`, and the sketch: `sketch/set { patch: { template?, rootDeg? } }`,
  `sketch/arm { template, rootDeg? }` (from a chord chip or a shelf chord), `sketch/disarm`. `Sketch = { template | null, rootDeg, armed }`; a hand-picked
  template clears `armed`. Refusals (empty chord, the caps, a source that will not reload) set `shelf.refusal`; it is cleared by the next successful stash, rename, move, delete, sync or reload (not by select or sketch actions).
- Reload (`shelf/reload`): a NEW tab at the end, which becomes active; every existing tab is untouched. The stored generator inputs are rebuilt, the stored
  subset is re-resolved against that field (`resolveSubset`, exact monzo else 0.5 c; nothing found selects all), the mode is the stored root's. The tab links
  to an owner by the M7b owner lookup (`ownerOfTab`) only when that owner's generator has the same `genKey` as the stored inputs (a stale preset label is
  not trusted; the lookup is retried without the label and the tab then takes the inputs that matched, so a stale label is cleared; when two presets share a `genKey` the lookup's own order decides which one it links to); otherwise the tab is unlinked and `gen.preset` is cleared. Nothing is created in the library, no
  Recent entry. The tab records `fromChord` (stored as `from` in `tabs.v1`, copied by Duplicate), so chords stashed from it get `parent`.
  `shelf.lastReload = { id, found, missing }` says how many source pitches the rebuilt field had. Refused at 12 tabs, with no source, or when the
  inputs do not build.
- Persistence (`shelfStore.ts`, effect in `LabProvider`): written only when `shelf.chords` differs from the restored one (no write on mount); a chord whose
  pitches are damaged (not 1 to 64 usable pitches) is dropped at load (a wrong chord is worse than none), an unusable `source` only loses the source, every
  other field falls back to its default; unknown extra fields are not kept; a monzo that is not plain loses its monzo and keeps its cents. A storage event for
  the key (or a clear) dispatches `shelf/sync`. Selection, sketch, `lastStashed`, `lastReload` and `refusal` are runtime only.
- Pure helper for the sketch row (lib `sketch.ts`): `matchToField(field, rep, pitches, tol)` gives, per pitch, the field index it lands on (repeat-aware) or the
  signed distance in cents (field note minus pitch, so positive = the nearest field note is above) to the nearest field note, wrapping around the repeat.

#### Ghost marks (M8a follow-up)

A sounding pitch that matches no field note of the tab (`litIndex` = -1: Sketch outsiders, hold 4 on an off-field root, retuned notes off the field) is shown as a **ghost**: a dashed, unfilled circle in `--mark-green` (the sounding color, H-2) at its true place.

- Model: `Planned.ghost` (cents above 1/1, set by `pitchesPlan` when `src` is -1, from the light cents so Parallel shelf chords ghost at the field-absolute pitch) and the retuner's off-field voices. `useLabAudio` counts them by pitch (`ghostLights`, a second `LightCounter` keyed by `ghostKey` = cents to 0.01 c, so two sounds of one pitch end together) and reports them in `sounding { ghosts }`; `LabState.soundingGhosts` / `Lab.soundingGhosts` hold the cents; field lights (`sounding`, `soundingMarks`) are unchanged. Panic, field change and unmount clear them with the other lights. Runtime only.
- Coverage: every off-field sounding source reports a ghost through the same counter: `pitchesPlan` (Sketch, hold 4/5, shelf), mode previews (`modePreviewPlan` tones with no field light, e.g. a pure Parallel degree, ghost at the pitch it sounds at above 1/1), strip targets (`stripPreviewPlan`: the target keeps its strip mark and also ghosts at `note - dev`), and the retuner. `light(i, on, markOnly, ghost)` counts the field light and the ghost separately. Play scale and the computer keys always light a field note (`slotPitch` plays subset notes), so they never ghost.
- Pure part: `state/ghosts.ts` (`ghostKey`, `ghostCents`, `ghostsOf(field, repC, cents)`: reduced into the repeat, de-duplicated, sorted, with the signed distance to the nearest field note and the tooltip text; the ratio is not shown because only the cents are kept).
- Drawing: `components/GhostMarks.tsx`: the ring (Chromatic view only, a dashed circle on the ring with a `<title>` and aria-label; the Fifths view has no place for an arbitrary pitch), the tuner strip (`StripGhosts`, a dashed circle level with the marks at the pitch's column) and "+N outside" in the ring caption (`OutsideCount`, both ring views). No label text is drawn, so `labelLayout` is not involved. The other views (lattices, keys, field tables, iso keyboard) show nothing.

### Composite gamuts (M8c step 1: data layer, merge lib and Developer options; step 2, the UI, is the last subsection)

Decision H-8. A composite combines chords, subsets and single notes from any generator into ONE gamut. Everything is plain data.

- Merge rules (lib `composite.ts`, pure): the repeat is the FIRST item's source repeat (`item.rep`), else the current tab's repeat when the composite is
  empty or the first item has none; every pitch of every item is reduced into `[0, repeat)` (a Bohlen-Pierce 3/1 chord in an octave composite lands in the
  octave; the monzo survives when both pitch and repeat have one, else cents-only). Pitches are placed in item order: a pitch within the merge tolerance
  (inclusive, linear distance inside the repeat, no wrap-around at the repeat) of a note already placed merges into the nearest one. `keep: 'first'` (default) keeps
  the pitch placed first, `'recent'` the last; the same pitch (within 1e-6 c) with an exact monzo always beats a cents-only twin. Each merged note keeps its
  `origins` (item ids). With tolerance 0 only identical pitches merge, so the pitch set is independent of the item order.
- `previewAdd(items, candidate, fallbackRep, opts)` is what step 2's popup draws: `added` (new notes), `common` (merged into an existing note: the pitch and the note
  as it was), `dropped` (vanish because, once reduced, they coincide with an earlier pitch of the same item: an octave doubling), `already` (an item with the same
  pitches is in it, `samePitches`), plus `before` (the composite's notes) and `rep`.
- State (`LabState.composites: CompositesState`): `list` of up to nine `Composite { id (1..9, its number), name ("Composite N", renamable), items, next, updated }`,
  `recent` (most recently used ids first, runtime), `lastAdded` (runtime) and `refusal`. An id is the lowest free number: freed on delete, reused only after.
  Actions: `composite/new`, `/rename`, `/delete`, `/clear`, `/addItem { to: number | 'new', item, date }`, `/removeItem`, `/use`, `/sync` (storage event), and
  `/openTab { id, merge? }`. A duplicate item (same pitches in any order), a full composite (64 items), an item with no usable pitch or over 2048, a missing number,
  nine composites and an empty or unbuildable `openTab` are refused WITH a reason in `composites.refusal` (never silent; cleared by the next success). Items are
  made plain as a load does (`sanitizePitch`), so what a session holds is what a reload gives back.
- Composite generation method: `Method` gained `'composite'` (not in the `METHODS` picker; only `composite/openTab` makes it, `gen/method` to it without a snapshot is
  ignored) and `GenSpec.snap?: CompositeSnap { id, name, rep, notes }`. `generateField` builds the field from the snapshot (`buildField`, so the prime filter still
  applies; the `rep` text is only a label). `openTab` builds a NEW tab at the end (current tabs and the library untouched, the new tab active, all notes selected):
  a snapshot of the merged notes at that moment (`gen.snap`); editing or deleting the composite later changes nothing. The tab "records fromComposite" as `gen.snap.id` and
  `gen.snap.name` (no separate Tab field, so a chord stashed from it carries it in its `source.gen`). The generator header (step 2) reads `gen.snap`.
- Storage: `tabs.v1` snapshots store `gen: 'composite'` and `snap` (entry by entry: an unusable note is dropped, a cents-only note loads cents-only, an unusable repeat or an
  empty list loses the snapshot, the tab keeps method composite and shows the error with its stored selection held as `pending`). `genToStored` includes `snap`, so a shelf
  chord stashed from a composite tab (and an Auto-saved generator made by `subset/add` on one) reloads through the stored snapshot: `shelf/reload` rebuilds the field from
  `source.gen.snap`, no library write, no link. `genKey` of a composite is its pitches (`generatorKey` in lib `library.ts`), not its name. Old data is unchanged: no
  `snap` key is written unless the generator has one.
- `composites.v1` (`compositeStore.ts`, effect in `LabProvider`): written only when `composites.list` differs from the restored one; a storage event dispatches
  `composite/sync`. An item with damaged pitches is dropped at load; an unusable `source` or `rep` only loses that; an invalid or repeated number takes the lowest free one;
  beyond the caps the rest is not loaded.
- Developer options (`developer.v1`): `mergeTolerance` (0 to 50 c, default 5) and `mergeKeeps` (`first` | `recent`, default first), passed to `composite/openTab` and
  step 2's preview by the UI. RULE (human, 2026-11-15): the Developer menu is grouped into sections by what and where a control affects: Tooltips (tooltips, delay), Mode
  display (sign always, keep the mode root), Playback and keys (linked melody root default), Composites (merge tolerance, merged note keeps). A new control goes into the
  section it affects, or a new one. Storage keys and defaults of the old options are unchanged.

### M6 genus and odd limit (H-27; data layer M6a, UI M6b thin slice built, waiting for the human to look)
Additive: old data loads unchanged, versions stay 1, nothing new is written unless set. Lib side: `genus.ts` and `buildField(..., odd?)`, see the lib README "Genus and odd limit".
- **`GenSpec.oddLimit?: number`** (any method; absent = no filter, the reducer deletes the key, never `null` or 0). A note whose ratio has a larger odd limit is dropped in `buildField` beside the prime filter; a note with no ratio (EDO, cents) is KEPT (human decision D2). `generateField` passes it for every method and for a composite snapshot. `capOddLimit` (`generate.ts`: whole number from 1, digits accepted, capped at `MAX_ODD_LIMIT` = 4095, else null) is the one reader for the form, the reducer and storage.

  (`keepNew`, `pickScale`, `pickKind`, `pickStretch`, `pickM`, `pickOdd`, `pickRef`, `cmpRef`, `cmpOdd`, `cmpM`). Every field is optional with a
  default, so an older snapshot still loads and unknown fields are ignored. A prototype `preset` index maps to the preset name.
  The selection is stored as cents, not indices, and re-matched (within 0.01 c) when the field is rebuilt.
- Sanitizing is entry by entry: a bad tab, subset, column, view or share is dropped (or defaulted) and the rest is kept, so
  a future new view or panel cannot wipe a stored layout. Only a value with no usable entry at all falls back to the defaults.
- Restore runs synchronously in the reducer's initializer, before the first render. Each save effect writes only once its
  part of the state differs from the restored object, so nothing at all is written on mount (a stored value the page could
  not fully use is never overwritten by what it made of it). A `frozen` provider never reads or writes storage.
- A tab restored while its inputs do not build (a repeat saved mid-edit, e.g. `2/`) has an empty field; its stored selection
  and mode are kept as `Tab.pending`, written back by `toSnapshot` and re-matched by the first good build.
- A failed write (storage full or blocked) is reported by the `save*` functions (`false`); the page shows "Not stored" in the
  saved-subsets list (`Lab.storeFailed`). The library is re-read on the `storage` event (`generators.v1`), so a second window cannot wipe the
  subsets saved in the first (tabs and settings are last-writer-wins). There is no cap on the number of subsets beyond the load sanity caps.
- Text and number inputs that rebuild the field (repeat, generators, CPS factors, custom list, counts) commit after typing
  pauses (120 ms, as the prototype's `regen()`), on Enter and on blur, so typing "3/2" never rebuilds for "3".
- Prototype data lives on another origin (`file://`) and does not carry over automatically.

### Audio engine (`audio/`)

Lab-local, Web Audio only, no shared audio code (decided 2026-11-13; may be promoted to a shared module later).

```ts
new VoiceEngine({ createContext? })          // the AudioContext is created on the first sound (a user gesture)
engine.setVolume(0..1); engine.setTimbre('sine' | 'harmonic')
engine.setPartials(count, rolloff)           // A1: the harmonic wave for voices started later (clamped 1..16, 0.5..1)
engine.setReverb('dry'|'room'|'hall'|'custom', mix 0..1); engine.setCustomImpulse(ImpulseData | null)
engine.decodeImpulse(bytes) -> {sampleRate, channels} | null   // the browser's decodeAudioData, first two channels
engine.start(id, hz, amp?) -> boolean        // a held voice at any Hz; no-op if id sounds
engine.stop(id)                              // release (setTargetAtTime, from the computed level)
engine.glideTo(id, hz, ms)                   // exponential frequency ramp of a held voice (the retuner, M7)
engine.blip(hz, delaySec, durSec, amp?)      // a timed voice that releases itself
engine.stopAll()                             // panic: every voice fades within ~0.1 s; scheduled-but-unstarted ones are canceled
engine.dispose()
```

- A voice is one oscillator through one gain into a master gain and a gentle limiter. `harmonic` is a single
  `PeriodicWave` of 7 partials with amplitude 0.88^(k-1) (the Sethares default, matching the roughness math), so a glide is one ramp.
- **Reverb and partials (A1, H-31).** One shared convolution reverb. With the preset Dry (default) the graph is exactly the one above.
  Any other preset builds, the first time it is in effect, the wet path `master -> send -> convolver -> wet gain -> limiter` and puts a dry
  gain between master and limiter; Mix sets the two gains equal-power (`reverb.mixGains`: dry = cos, wet = sin of mix x 90 degrees, so mix 1 is the
  reverb alone). A preset change fades the wet gain (about 30 ms), then replaces the convolver; the panic fades it over about 0.15 s and then also replaces
  the convolver (a new one has no memory, so the tail cannot come back when the wet gain returns). Room (0.9 s) and Hall (2.8 s) are generated
  from seeded decaying noise (`reverb.makeImpulse`, stereo, one-pole smoothed). Custom with no impulse loaded plays as Hall. The convolver
  normalizes (`normalize = true` before the buffer is set); an impulse at another sample rate than the context is resampled.
  `ui.reverb` = `{ preset, mix }` in `settings.v1` (additive, `sanitizeReverb`); the impulse itself is one IndexedDB record `reverb-ir`
  (`audio/impulseStorage.ts`: name, sample rate, channels; every call failure-tolerant, a failure means "none") and is shared at runtime through
  `audio/impulseStore.ts` (read once per page load by `useLabAudio`; a Custom preset whose impulse cannot be read becomes Hall with a one-line
  note). A picked file is checked by `reverb.loadImpulseFile` (over 8 MB, not decodable, over 12 s). The Developer option `soundFollowsRoughness`
  (default on) makes `useLabAudio` give the engine the Roughness Partials and Rolloff (`state.retuner.settings.scorerOpts`: one set for the whole
  lab, not per tab) through `soundPartials`, which clamps to 1..16 and 0.5..1; off gives 7 and 0.88. The controls are in the Sound settings
  popover (`components/ReverbControls.tsx`, under Volume); the switch is in the Developer menu, section Sound.
- Envelopes are scheduled (`setValueAtTime`, `linearRampToValueAtTime` for a 12 ms attack, `setTargetAtTime` for the release); the
  release starts from the level computed from the attack, never from a read of `gain.value`.
- `useLabAudio` maps keys to voices: the computer melody keys `zxcvbnmasdfghjkl` (16 slots, melody keys v2) and pointer presses on dock keys hold a
  voice (slot i = degree i mod N, floor(i / N) + the melody shift repeats up; see "Keyboard modes, melody shift and linked melody"); Play scale, Play chord (the highlighted chord, else the subset),
  a chord chip click and the field table's play button schedule timed voices. Hz = 1/1 Hz x 2^(cents/1200), with the mode
  root at 1/1 Hz or not (`modeAtBase`).
- What sounds is reported to the lab state (`sounding`, a set of field indices; counted per index so overlapping voices light
  until the last ends), and every view lights it with the `--mark-green` look (H-2).
- No stuck notes: window blur, `visibilitychange` to hidden, a change of field (tab switch, regeneration), the Stop button and
  unmount all call `stopAll` (a field change only when something sounds). Keys are matched by `event.code` (the physical
  key) and released by it, so Shift cannot leave a note stuck. A panic fades a voice that is already releasing from its decayed
  level, and `glideTo` anchors at the pitch an interrupted glide has reached. Typing in an input, textarea, select or contentEditable never plays. Alt+1 to Alt+9 switch tabs.

### Retuner (M7)

Engine: `src/lib/harmonic-field/retuner.ts` and the scorers (unchanged, `vectors.json` is the contract). The lab only feeds it.

- A **card** is a whole tab snapshot (`snap`: generation inputs, subset, mode; the plain `toSnapshot` shape, so M8's shelf can
  restore a source from it) plus `notes` / `rep` derived from it (`cardFromTab`: the subset read from its mode root, the same
  `rotateSubset` the keyboard plays). Cards start where the one **Parallel | Relative** switch (`ui.modePlayback`, mirrored in `RetState.relative`) puts them, as `relHz` does for the keys and Play scale: Parallel, the root on 1/1 Hz (`HOME_BASE`); Relative, the root at its own mode root's pitch above 1/1 (`RetCard.root`, from the snapshot's subset and mode; `startBase`). `bases[i]` is where card i's root sits
  now (exact monzo while JI); drift is the chosen card's base minus its start (so the I-vi-ii-V-I vector gives 80/81 in either mode). **Card 0 is home**; "Make home" moves a card to
  the front. Adding, moving, making home or deleting a card, and switching Parallel | Relative, resets the run (every root back on its start: 1/1 Hz in Parallel, the card's own mode root in Relative; card 0 active, no history);
  rename does not. **Reset roots** does the same without touching the list.
- **Fill cards** (M7c; `state/fillCards.ts` pure, `components/FillCards.tsx` the modal, a button under the card list). A centered
  modal with three sources, each on its own: **Modes** of the current subset (one card per subset note as the root, named "Mode 1"
  ... as the Modes panel numbers them), **Keys that fit** (the Keys panel's complete transpositions, "Key on 9/8"; the key's found
  notes, its root the mode root) and **This generator's subsets** (`subsetsOf` the tab's owner, each resolved against the tab's
  field with `resolveSubset`; no match = skipped, a partial match keeps the notes found). Default Modes + Keys. Every candidate is a
  whole tab snapshot built with `cardFromTab` (`{ ...tab, sel, mode }`). The preview drops duplicates (same notes in cents to 0.01 c
  at the same root; across and within sources, the first source's name wins, order modes, keys, subsets) and anything equal to an
  existing card, and suffixes a name already taken (" 2"). Each row is tagged against card 0 (the tab's own card when the list is
  empty): **retuned notes** when it has the same number of notes and every degree is within 30 c of home's degree (circular), else
  **different notes**. Rows are checked by default; the footer reads "n cards will be added; m would exceed the 24-card limit": the
  cap counts stored dormant cards too (`planFill`), what fits is added in list order. **Apply** sends each checked card through the
  unchanged `ret/add` (existing cards stay in place, new ones are appended, the run resets). Worked example (tests): 5-limit major,
  held degrees 2, 4, 6, Manual pivot degree 4, Roughness, Freestyle: major alone scores 5.63 (9/8:4/3:5/3); with the Modes added the
  engine picks the mode with 10/9:4/3:5/3 (4.45); the 16/15:4/3:8/5 mode scores 4.54; all modes are tagged "different notes".
- The retuner is on or off (transient). While it is on and has a card (`retunerLive`), a computer or dock key is a degree of the
  **active card** (slot i = degree i mod N of that card, floor(i / N) repeats up), not of the tab. `ret/down` records the held
  key (`{ key: slot, deg, oct, t }`), and with trigger **Auto** and two or more keys held it runs `runStep` (`retuneStep` with the
  settings' pivot, anchor and scorer, `refHz` = the 1/1 Hz setting); **Manual** waits for `ret/retune` (the Retune now button).
  Nothing runs on key-up. When the engine keeps the active card (no pivot, nothing held, no candidate) only `last.why.reason`
  records why.
- Pivot modes manual | lowest | highest | recent | longest; **Manual is by degree** (`manualDeg`, 0-based in the state, shown from 1
  in the panel; the degree need not be held; decision 2026-11-14). Lowest/highest compare slot numbers, recent/longest compare
  key-down time. Defaults: pivot Longest, anchor Freestyle, trigger Auto, scorer Roughness (Sethares, 7 partials, rolloff 0.88),
  glide 120 ms.
- **Voices** (`useLabAudio`): the retuner's held voices are reconciled with `state.retuner.held` after each change (`syncRetuner`):
  a new key starts a voice (id `rt<slot>`) at the active card's pitch, a released key stops it, and a voice whose pitch moved after
  a retune glides there over `glideMs` (`engine.glideTo`; a pivot that does not move does not glide). Window blur, a hidden tab, a
  field change and the Stop button panic as usual and also release the retuner's keys.
- **Lights** (H-2): a retuned pitch lights the tab's FIELD note it coincides with (within 0.5 c, reduced into the repeat; `litIndex`), selected or not, as the tab's own keys light: in Parallel the pitch above 1/1 Hz is read from the tab's mode root (pitch + its root cents), in Relative as absolute pitch. A pitch with no field note lights nothing. The sync effect also depends on the field and the 1/1 Hz
  setting, so changing them while keys are held cannot leave stale pitches or lights. The main views stay on the tab; the retuner panel shows the active card. Known limit: a computer key and a dock mouse press on the same slot share one held entry, so releasing one releases both.
- Panel: cards (rename in place, up/down, make home, delete, add the current tab), controls (on/off, trigger, Retune now, Reset
  roots, pivot, manual degree, anchor, scorer and its options, glide), "Why this card won" for the last retune (each card's root,
  predicted chord in Hz, score, rank, winner; sortable columns; the same chord under all four scorers) and the drift readout
  (cents, as a ratio when exact) with the history of the last 24 retunes. Card numbers are shown from 0 (card 0 = home), degrees
  from 1.

### Selection look per view

Selection is "1px border plus 1px outline in `--text`" where an outline fits (saved row, pinned note, chord chip). Dots differ by
medium: SVG views (ring, lattice, iso keyboard) draw a selected note as a filled `--text` dot and an unselected one as a hollow
`--text-subtle` dot, a pinned or hovered note gets a ring (`selRing`); the strip draws a colored line (selected) against a faint
one; the dissonance curve draws bright versus faint marks; the 3D lattice uses sphere size and brightness. Sounding is always
`--mark-green` and the highlighted chord always `--mark-blue`, in every view. These per-view variants are deliberate (each
medium needs its own second channel); a single shared look is not worth the loss of legibility.

### The Relative picker's Color menu (M8o, H-37, H-38)

- Modules: `state/intervalColor.ts` (the metrics, fixed vs fit bounds, the intensity mapping, the legend helpers, `errorStripPosition`, and the Monzo cells that color a cell by "only that exponent changed" with the Exact or Reduced octave), `components/RelativeColorMenu.tsx` (the menu), `components/RelativeColorLegend.tsx` (swatches and shaded bars) and `components/SignedErrorLegend.tsx` (the Error strip).

- **Channels (M9c, H-40).** The single Color metric is gone.   - Hue Off and Brightness a measure: the BLUE ramp (`hueTint(BLUE, strength)`, `BRIGHT_HUE`), bright = strong in both schemes. Marks use the Radix steps `BRIGHT_MARK_STEPS`, fills `BRIGHT_FILL_STEPS`, and the plain text color takes over from `BRIGHT_PLAIN_TEXT_FROM`.
  - Hue a family and Brightness a measure: the hue's own steps (the same step numbers of its own hue; Prime keeps its wheel blend, Interval class its wheel, Error sign orange or cyan); Error sign + |error| is exactly the H-38 tile.
  - Hue a measure (F11 to F14): the ordered viridis-like ramp `MEASURE_RAMP` (Radix hues only: dark blue, cyan, green, yellow; light the reverse, so the strong end is always the higher-contrast end), cut into `RAMP_LEVELS` colors by `rampColor` (`color-mix` in oklch between neighbor stops); `rampTint` builds the tint, with separate `marks` stops for dots and `fills` stops for cells and cards. A Brightness on top mixes the fill toward the panel (up to `RAMP_FILL_FAINT_PCT`) or the mark toward the text color (up to `RAMP_MARK_TEXT_PCT`).
  - Both Off: no tint (plain). A measure with no value (an irrational note, or Entropy before its curve exists) gives no tint.
- **Guard for the ramp steps.** The steps are not tuned by eye: `state/intervalColor.test.ts` computes WCAG contrast and OKLCH lightness from the Radix values (no browser) and fails when a ramp stops satisfying them: dark marks at least 2 : 1 at the faint end and 4.5 : 1 at the strong end against the panel, rising; light the mirror; fills lifted off the panel with the text color at least 4.5 : 1 on every fill; for `MEASURE_RAMP`, OKLCH lightness monotone along the stops (rising on dark, falling on light), every mark stop at least 2 : 1 on the panel with contrasts rising and the strong end at least 4.5 : 1, and the plain text at least 4.5 : 1 on every fill stop; the tints and the legend bars are sampled from the same constants. - **Legends** (`components/RelativeColorLegend.tsx`, memoized; hovering gives it ONE value, `LegendMarks`, from `legendMarksOf`): a HUE part (Prime chips, Interval class chips, Error sign: three chips, or the lab's `SignedErrorLegend` strip when Brightness is |error| so the strip is sign and size, or a hue BAR for a measure on Hue, `hueBarColors`, sampled from `rampTint`) and a BRIGHTNESS bar (`brightBarColors`, sampled from the same functions that color the cells: blue ramp with Hue Off, a neutral ramp when a Hue is set). Two bars stack with titles. Each bar has its end values (`legendBounds`, `legendNumber`), the strong end named, and a tick (an arrow when the value is beyond the bar's ends); the |error| bar has one segment per band; the error strip's tick is placed by `errorStripPosition`. - **Near radius.** `state/nearRadius.ts` (pure, no React): Near's radius used to be an Odd limit / Tenney toggle (`MetaSettings.measure`, removed); it is now `relColor.near.radius`, any of the five measures (`RADIUS_LABELS`, `RADIUS_UNITS`). - **`MetaSettings` (`components/RelativeMenu.tsx`, runtime only, two sets: Near button and Ctrl+click)**: `measure` is removed; `entropy: boolean` is added (the Near "Entropy curve" overlay, below). Radius is a stored channel, the overlay a runtime switch.

### Monzo header split, shift buttons and label click (M9f, H-42)

Spec: `arcs/harmonic-field-lab/SCENARIOS.M9f.md` (F1 to F25). Help keys: `monzoSplit`, `monzoNorm`, `monzoOctaves`, `monzoFit`, `monzoLabelSet`, `monzoShift` (`texts.ts`).

- **The split rule** (`state/primeSplit.ts`). Prime p contributes a_p = |e_p| x log2 p. L1: share = a / sum a, total = sum a. L2: share = a^2 / sum a^2, total = sqrt(sum a^2). L-inf: bar = a / max a, total = max a, no percent: "max" under the largest prime (the first one when tied). Count octaves off drops prime 2 from every sum and draws a dashed ghost outline in its column (no number). Fit scales every bar by the largest counted value so the biggest fills the band; the ghost is capped at 1. Numbers never change with Fit.
- **Which interval is split.** The one the colors measure now: the hovered pin card's monzo, else `shownMonzo` (the painted monzo, or its inverse while Alt is held), folded by Monzo Octave, then through `measureOf` (so Landing splits the landing from the source, and the held backtick flips it). ### Harmonic entropy (M9, H-39)

- **Lib** `src/lib/harmonic-field/harmonicEntropy.ts` (pure, in the barrel): HE(c) = -sum p ln p over every reduced ratio n/d with n x d below the limit N, p proportional to exp(-(c - c_j)^2 / 2s^2) / sqrt(n_j d_j): the Gaussian blur s of the ear times a 1/sqrt(n d) weight, in nats, lower = more consonant (only shape and relative depth matter; the level depends on N). `heCandidates(N)` lists the ratios between -300 c and 1500 c (so the 0..1200 c curve has no edge distortion) sorted by cents; `heCurve(cands, s)` is the 1 c curve (1201 values, a sliding window of `HE_WINDOW_S` = 8 s); `heAt(cands, cents, s)` is one interval exactly (folded into 0..1200 c); `heCurveAt` interpolates the curve; `heRange` is its min and max; **`heFixedRange`** is the min and max EXCLUDING `HE_UNISON_EXCLUDE_C` (30 c) around 0 c and 1200 c, the Fixed bounds of the color ramp (without it the very deep unison dip would take the scale and crowd 3/2, 5/4 and 7/4 at one end; values beyond the bounds clamp to the strong end and are still plotted). `HE_LIMITS` 10k, 30k (default: converged; 10k shows an artifact dip at 1065 c), 100k, 250k, 500k; `HE_BLUR_MIN`..`HE_BLUR_MAX` 8..20, default 17. The estimate: `estimateHeBuildMs(N, msPerRatio)` = 0.316 x N ratios at the measured (else default 0.005) ms each; `formatBuildMs` words it ("under 0.1 s", "about 2 s"). Tests: `harmonicEntropy.test.ts` (dips at 1/1, 3/2, 4/3 and 5/4).
- **Store** `state/entropy.ts` + `entropy.worker.ts` (module-level, no React state): a curve is built once per (s, N) and kept in a memory `Map` (nothing on disk); single intervals (`source.at`) are computed exactly from the candidates and remembered per (s, N), so a hover never rebuilds anything. `requestHe(s, N)`: already built shows at once; otherwise the build starts `DEBOUNCE_MS` (150) after the last request (dragging the slider builds once; the very first build starts at once) and the previous curve stays shown while `building` is true. A build whose estimate is above `WORKER_MS` (200) runs in the module Web Worker; smaller builds, and every build where there is no `Worker` (jsdom, the page tests) or the worker fails to start or errors, run synchronously on the main thread (an explicit fallback, `buildSync`). A newer request terminates a running worker. React reads it with `useSyncExternalStore` (`useHeCurve(s, N, enabled)` asks for the curve while the component is mounted and enabled; `useHeStatus()` only reads the status): nothing is built until a consumer mounts, and a consumer re-renders only when a build finishes. The measured ms per ratio of the last build feeds the estimate. Tests: `entropy.test.ts`.
- **Consumers.** (1) The Dissonance view (`DissonanceView.tsx`): the HE curve is drawn behind the roughness curve on its own vertical scale (the Fixed range, `he.source.lo..hi`, clamped), labeled "Harmonic entropy", with each field note a dot at its exact value (`source.at`) and a readout row ("Harmonic entropy", min to max or the value at the cursor). Its header row holds the **s slider** `HeBlurSlider.tsx` ("s 17 c", `ui.heBlur`, one lab-wide value; the same component sits in the picker's Color panel while a channel is Entropy) and a "Building entropy..." note. (2) The picker's Hue, Brightness and Radius when Entropy (above). (3) The Near **"Entropy curve"** overlay (`mSet.entropy`, a checkbox beside Cents lines): the curve as a thin radial polyline in a band outside the ring (`HE_BAND_GAP`, `HE_BAND_H`) at each cent offset's own angle (the pitch at offset o is the center interval plus o, so a smaller Span draws only that arc), low entropy nearest the ring, scaled by the curve's own `heRange`; `RelativeMenu` passes it `he.curve`. (4) The Developer menu section **"Harmonic entropy"** (`DeveloperMenu.tsx`): the select "Harmonic entropy candidates (n·d <)" (`heLimit`), each option labeled with its estimated build time (the measured one after a build) and "Building entropy..." while one runs.

## Positional chords (M9 step 1: lib and data layer, H-9)

- **What**: a chord type is a STEP PATTERN counted in the ACTIVE SUBSET read from its mode root (lib `positional.ts`; `[2,2]` = every other note, a tertian triad in a 7-note scale). The pattern is the chord's identity, so it works in any tuning and any subset; the ratios are the result. A member that wraps around the subset is stacked above the root by one repeat (root position; voicings later, BACKLOG). Degrees are 0-based in the API (like `Sketch.rootDeg`), shown 1-based in labels. Ranking: `rankPositional` by Sethares roughness of the chord's SHAPE with its root at one common Hz (register-independent: identical shapes tie, then degree order; smoother first), the score is exposed. A step that is a multiple of the subset size repeats a field index a repeat higher in `members` (consumers that dedupe by field index must expect it). Naming: main label `2-2 on 4`, tail `7 of 12-EDO · 400-300 c` (the generator display name is a parameter), ratio `~ 4:5:6` only when every note is within 5 c of a chord template.
- **Patterns list**: `LabState.patterns: PatternsState { list: string[] (canonical texts, no duplicates, at most 40), refusal }`, defaults 2-2, 2-2-2, 2-2-2-2, 2-3, 3-2, 1-1, 3-3. Actions `patterns/add { text }`, `patterns/edit { at, text }`, `patterns/delete { at }`, `patterns/move { from, to }`, `patterns/restore`, `patterns/sync` (another window). Text is validated by `parsePattern` and a refused action sets `patterns.refusal` with a reason (cleared by the next accepted action). A stored empty list stays empty.
- **Storage**: NEW sibling key `hrifa.harmonic-field-lab.patterns.v1` `{ version: 1, patterns: [{ text }] }`; `chordfinder.v1` is NOT changed (saved templates load untouched; tested). Entry by entry (bad dropped, canonicalized, repeats kept once, cap 40), bad or all-bad data falls back to the defaults, no write on mount (`LabProvider` writes only when `patterns.list` differs from the restored one), a storage event dispatches `patterns/sync`.
- **Chosen pattern** (superseded by M8f): `ui.positionalPattern: string | null` in `settings.v1` is still loaded and saved (optional: absent or damaged = null; no write on mount) and `chosenPattern(list, ui.positionalPattern)` still exists, but the Positional section no longer reads it (all patterns are shown as groups); the stored field is kept only so old settings round trip.

## Color-role mapping (H-2)

Fixed by the human (`DECISIONS.md` H-2, 2026-11-13). Colors come from the shell roles in `src/theme/THEMING.md` (neutral roles, `--mark-<hue>`,
`--tint-<hue>-bg` / `-text`), never from hex, palette shades or ad-hoc radii/shadows. Canvas or SVG drawing goes
through `markHue`. The prototype's own tokens map as follows.

| Prototype meaning (token) | Shell role | Second channel (color is never alone) |
| --- | --- | --- |
| Selected note (`--accent`, blue) | The state grammar's selection: an outline in `--text` (accent never encodes data); unselected dots are `--text-subtle`. | Outline weight and a filled vs hollow dot. |
| Highlighted chord (`--warn`, orange) | `--mark-blue`: the outline and edge of the chord's pitches (ring triangle and dots, dock keys, lattice, iso keyboard, strip). | An outline (not a fill) plus the "chord" label on the chips; never the only cue. |
| Sounding / lit (`--lit`, green) | `--mark-green` fill (dock keys use `--tint-green-*`), applied to every visualizer at once. | A larger dot or ring (the prototype scaled the dot by 1.6), a dot in the middle of a strip line and of an iso hexagon; no drop-shadow glow. |
| Sharp of target (`--sharp`, rose) | `--mark-orange` (the human's "amber"; the theme has no amber hue) | Bar above the zero line plus a `+` in its cents label. |
| Flat of target (`--flat`, cyan) | `--mark-cyan` | Bar below the zero line plus a `-` in its cents label. |
| Chord error, exact (band 0) | `--text` (neutral; tiles untinted) | The cents number itself (0.0). |
| Chord error, signed (H-38) | Sharp (error above 0): `--mark-orange` family. Flat (below 0): `--mark-cyan` family. The hue is the sign; an error is what is there minus what was wanted. | The printed signed cents value. |
| Strength by `errorBand` | Band 1 (< 5 c) faint, band 2 (5-15 c) normal, band 3 (15-30 c) strong; band 4 (30 c or more) is one Radix step past strong (`BAND4_LIFT`: Tinted fill, Outlined border, Solid fill). Text-only values mix the hue's text step into `--text` (`BAND_TEXT_MIX`). | The cents number. |

Notes on the mapping:

- The signed error scale (H-38, replaces the M4c warm heat family) is ONE rule for every error view (the table above): the hue is the sign (sharp, error above 0 = orange; flat = cyan: the tuner strip's `--mark-orange` / `--mark-cyan`; an error is always what is there minus what was wanted), the strength is the five `errorBand` bands, exact is neutral. One place: `state/tileColors.ts` (`signedBand`, `signedErrorTile`, `signedBandTile`, `signedErrorTileStyle`, `signedBandTileStyle` for fills in the lab's tile look; `signedErrorTextColor`, `signedBandTextColor` for text-only values, set inline; `SignedErrorLegend` draws the gradient strip with ticks at -30 -15 -5 0 +5 +15 +30 and the hover tick; the ring flags and dots use `--mark-orange` / `--mark-cyan`). Users: the Modes tiles (per pitch), the Pairs Error cells, table and legend (`components/SignedErrorLegend.tsx`, shared with the Modes legend), the chord card values (`ValueList` `errors`), the chord stat and Library roots table, the Sketch rows, the library ring's error column and the picker's Error metric and bar. The printed signed cents value is the second channel. `errorStats` (`state/chordSort.ts`) is signed: `worst` is the signed error of the largest-size note, `avg` the signed mean without the root; anything that sorts or filters by error uses `Math.abs`.
- Sharp (orange) and flat (cyan) mean the sign of an error everywhere in the lab (tuner strip, saved rows and the signed error scale above), never anything else; a sounding note gets the "sounding" dot.
- Sounding (green) and highlighted chord (blue) can appear on the same dot; the dot then shows the sounding fill with the
  chord outline, so both stay readable. Where green (sounding) sits beside the severity colors or blue (chord) beside the
  accent, the second channel carries the meaning: dot shape or position, outline weight, the printed cents number.
- Visualizer views use hues for roles only: the EDO-fit best bars are violet (not a data hue elsewhere), and a lattice
  stem takes violet, pink, red or yellow by prime, so no stem collides with chord (blue), sounding (green), sharp (orange)

### Help text: tooltips and glossary (help-text arc, H-16)

Settled by the human on 2026-11-16 (design record: `arcs/harmonic-field-lab/HELP-FORMAT.md`, arc archived as `ARC.help-text.md`). These are rules, not observations.
- **Tooltip surface (M4, 2026-11-16).** Every lab tooltip (`LabTooltip` in `components/ui.tsx`) uses the theme's own surface and text (`--panel-raised`, `--text`, a `--control-border` border and a shadow), not Mantine's inverted default, because the error-band text colors (`--rx-<hue>-11`) are chosen for the normal surface and were unreadable on the inverted bubble. The glossary entry `errorKinds` ("What each error measures") lists what the error means in each view: chord chip, Mode grid, Sketch tiles, tuner strip, Pairs.
- **Two forms of entry** (`texts.ts`). New: `{ term, help, teaching?, see? }`, arrays of blocks. Old: `{ term, text, see? }`, a PERMANENT short-entry form for entries of about 400 characters or fewer with no key or click gesture (about 114 of 224 entries today; the other 110 are in the help + teaching form). `normalizeEntry` turns both into one `TextEntry` (`help`, `teaching`, `legacy`, and `text`, one plain string of everything, which search, `LatticePanel` and tests read). An old entry is cut at its `Example:` (or `Example in ...:`) into a paragraph and an example block by `legacyBlocks`, so both forms go through the same renderer.
- **Help vs teaching.** `help` is what a tooltip shows and the glossary shows first: what it is and does, about 300 to 500 characters, at most 600, with an Example. `teaching` is the glossary only, below a rule: edge cases, worked examples, the numbers behind it, in small blocks (one idea each).
- **Blocks and order.** `p`, `keys` (rows: the key or gesture, then what it does) and `example` (the `Example:` label in italics). Order in a tooltip: bold term, the dynamic line (tooltip only: values and selections, in the same color as the rest, always directly under the term), help paragraphs, Keys, the Example last, a blank line between blocks. The glossary shows the same without the dynamic line, in SOURCE order (only the tooltip reorders), so keep the Example last in the source of a new entry.
- **Emphasis.** Bold for a name the reader can see on screen as text (a control or a panel; keys are written `{key:name}` and shown as a key cap); italic only for the `Example:` label and a term being defined. No raw HTML, and never `<` in a new-form entry (the guard bans it; old entries have none today but are not checked). Markup in strings: `**bold**`, `*italic*`, `{key:name}`.
- **Line rules (renderer, every entry).** A paragraph breaks onto a new line (not a blank line) at a sentence end when a line would pass `LINE_GROUP_MAX` (140 characters, about three lines in a tooltip); `glueUnits` joins a digit and `c` or `Hz` (`21.5 c`, `392.44 Hz`) with a no-break space (other units are not covered). Value lists on cards (`ChordCard`, `SketchRow`, `CompositesPanel`) use `components/ValueList.tsx` instead (breaks only between whole values, balanced): a card-text rule, not an entry rule.
- **Keys stay in sync.** `audio/shortcuts.ts` `SHORTCUTS` is the one table of the lab's key bindings (0, the holds 1 to 5, `,` `.`, `[` `]`, `=`, `-`, `E`); the handlers (`keymap.ts`, `useLabAudio.ts`, `plan.ts`, `Send.tsx`) and `{key:name}` in entries both read it. `,` `.` `[` `]` `=` are matched by physical key (`e.code`) first and use the table value only as the fallback, so changing one of those values also needs its `e.code` changed. A key named in a `Hint` `dynamic` or `Tip` `extra` string must be interpolated from the table (`${SHORTCUTS.holdOwn}`): those strings are not markup. Alt+1 to Alt+9 (tabs) is a digit range and stays plain text. Entry terms are plain text and are not checked against the table; only the Parallel | Relative key has a plain-text guard.
- **Tooltip components** (`components/ui.tsx`). `Tip` shows a glossary entry by key; `Hint` is the dynamic tooltip (optional `k`, `label`, `dynamic`) that replaced every dynamic native `title` that went through `useNativeTitle` (now removed); both sit on `LabTooltip`, the wrapper that makes the INNERMOST tooltip win when tooltips nest (the outer one is hidden while an inner one is hovered or focused). `LabTooltip` does NOT apply the Developer on/off and delay: every caller spreads `{...useTooltipProps()}` itself (`Tip`, `Hint`, the chord card), and a bare `LabTooltip` ignores them. A host with `display: contents` has no box and cannot carry a tooltip (it opens at the screen corner): attach it to a real box. A disabled button needs the `.hintHost` span to get hover.
- **Guards.** `texts.test.ts` (on NEW-form entries: help at most 600 with an Example, no `<`, every `{key:}` in the table; on every entry: no inline `Example:`, every `see` key exists, the sentence-line rule; plus a test of `glueUnits`), `components/help.test.tsx`, `components/tooltips.test.tsx` (nesting), `HarmonicFieldLab.hints.test.tsx` (order, tooltips off, disabled Reload, no `nativeTitle` left under `components/`, and a source guard: no `title=` attribute on a lowercase JSX tag under `components/`; component props such as `<Strip title=` and SVG `<title>` elements are allowed; it can miss a `>` inside a quoted attribute string).
- **No native `title=` on a DOM tag** (native tooltips arc, 2026-11-16): the last seven (`GhostMarks`, the live roughness data span, "Lower is smoother", the Shape and Pitch explanations, the shelf slot's "Computer key", the tuner-strip caption) are `Hint`s. The strip caption hangs on the strip's axis labels (the gutter), not on the plot, so sweeping the plot (hover and hold to play) never opens a bubble over it; the plot is a `role="group"` named by the caption. A `Hint` on a focusable container's ancestor also opens on keyboard focus (focus bubbles): put a `Hint` on the smallest host that fits.
- **Native browser tooltips that remain** (SVG `<title>`s: plain text only, the browser's own delay, ignoring the Developer tooltip settings): the mode-root chevron (`ModeRoot.tsx`), ghost marks on the ring (`RingStats`), the dissonance and roughness marks (`DissonanceView`, `RoughnessView`) and lattice nodes (`LatticePanel`). They wait on the unified help panel idea (BACKLOG): do not convert them to per-mark bubbles before that is decided.

Two layers: a static placeholder layer (muted `0.00` and "0 notes", chart axes, ticks and baseline, readout rows whose value slots are invisible blanks of fixed width, an empty pair box of reserved height) is always mounted and never changes; every drawn item sits in a `.liveData` layer that fades over it (`data-phase` live | dim | out | idle), so nothing switches between two subtrees. One attribute on the root, `data-state` (idle | sounding | hover | linger | fading), drives both layers' opacity: the placeholder TEXT is hidden (`visibility: hidden`, also `aria-hidden`) whenever the data layer shows and crossfades back only while the data layer fades out or idle; placeholder shapes (axes, baseline) stay. Placeholder and data layers use the same elements and classes, and every value sits in a slot whose width is fixed in CSS (`--live-total-w` 5.5ch for `0.00` / up to 99.99, `--live-count-w` 9ch for `12 notes` with `note`/`notes` sharing it, `--live-slot-w` 18ch / 10ch / 14rem for the three readout rows, right-aligned, ellipsis), so no width depends on the text and nothing moves between states. The pair box has a reserved fixed height and holds ONLY real pairs (2 notes: one bar, 3: three, ...; never placeholder bars in any state); the space below the bars stays empty and the list scrolls inside the box when there are more pairs than fit.
- Field marks and one-note sources (follow-up). (1) Faint field marks: every note of the active field (`base.field`) is marked on the curve at `(c - lowest) mod repC` above the lowest shown note (0 and a repeat are one unison mark), as a short thin `--text-subtle` line at the baseline (`.liveFieldMark`, shorter and thinner than the chord's own full-height marks). Field notes that are one of the shown notes (same reduced interval) are skipped, so nothing is drawn twice; none in idle. They sit in a second `.liveData` group inside the chart svg (after the slider rect so each can carry a native `<title>` and `aria-label`: `<note> against <lowest note>: roughness <v>`, value = `dissonanceAt(interval, lowest Hz)`), fade with the data layer, and add no DOM outside the svg. Pure math: `fieldMarks` in `liveRoughness.ts`, memoized on the shown notes and the field. (2) A hovered note (`lab.hover`) and a pinned note (`lab.pin`) are one-note chords, silent. Source order: sounding, hovered chord, hovered NOTE (tag `note`, `--mark-blue` like hover), lingering last chord, PINNED note (tag `pinned`, marks in `--text-muted`), idle. A pinned note therefore shows only after the linger has fully faded; a hover during a linger shows at once. One note shows its total (its own term), its curve, the faint marks and no pair bars. `data-state` is `hover` for both note sources.
- Live chart labels and ticks (second follow-up). The svg is 360 x 220 (bottom margin 54: tick row under the baseline, then a LABEL BAND of 3 lanes, 11 apart, from `BAND_Y`), constant in every state. Dip names are placed by the pure `state/chartLabelLayout.ts` (`layoutChartLabels`): natural spot under the dot's x in lane 0, next lane down when the estimated box (`labelBox`, 5.4 per char, pad 2.5) overlaps a placed name, clamped inside the plot x range (first and last dip anchor start and end), shrunk to `minScale` 0.8 before overlap is allowed, otherwise dropped (the dot keeps its `<title>`). A thin vertical `labelLeader` (lab.module.css, the ring's style) joins the dot to its name when the name is more than 6 below the dot or in lane 1 or 2. The Dissonance view draws the same leader from the dot to any label moved to lane 1 or 2 or anchored at the start or end. No help text for any one-note state; the idle hint is centered in the empty plot. Each faint field tick carries `data-subset` (field note in `lab.selected`): in-subset `--text-muted` at 0.8, others 0.28, and `(not in subset)` in their title and aria-label.
- Register and real pitches (third follow-up). (1) What is scored: every sounding pitch AS PLAYED. The audio hook (`useLabAudio.ts`) counts each started voice by its real Hz (`pitchKey`, hundredths of a cent, independent of the 1/1 setting) and `report()` dispatches `soundingPitches` (`{ c, src }`: cents above 1/1 from `1200 log2(hz / ui.baseHz)`, the field note it lights or -1), so stacked octaves are kept (D G C stays 200, 700, 1200 c). Sources: computer and dock keys, hold 1/2/3 previews, chips, shelf, Sketch and Positional plays (all through `light(..., hz)` from the plan's `Planned.hz`, the held note's `hz`, `slotHz` for a key release, the retuner's voice Hz, the linked melody's Hz). Parallel mode's root shift is therefore in the sounding pitches (the real register); the Shape register ignores it. A lit state that carries no pitches (a test dispatching `sounding` directly) falls back to the old reduced field indices. A hovered chord: `lab.setChord(set, pitches?)` stores `chordHoverPitches`; Positional rows pass the chord's stacked field-absolute pitches, shelf slots their `pitches`, the Sketch row its full chord (off-field notes included); chips and CPS cards pass none and use the field cents of their members (a field chord by definition; it cannot carry a stacked pitch). Hover under Parallel uses the field-absolute pitches, not the shifted sound. A hovered or pinned note is its one field pitch. Ghosts are unchanged. (2) Register switch (`Shape` | `Pitch`, aria-label `Roughness register`, in the fixed 13rem right slot of the head row, tooltips on the options): `Shape` (default) puts the lowest shown note at `POSITIONAL_BASE_HZ` and scores the intervals (`roughnessOf`, so the total equals a chord card's score for the same chord); `Pitch` scores each note at `ui.baseHz * 2 ** (c / 1200)`. The curve, pair bars, dips and faint field marks use the same register. Stored as optional `register` ('shape' | 'pitch') in `ui.viz[id]` (`RoughRegister`, sanitized `oneOf`, absent = `shape`, no write on mount). Tests: `HarmonicFieldLab.roughness2.test.tsx`.
- Dissonance curve label band: the Dissonance curve view uses the same band as the "Live chart labels and ticks" bullet above: its svg is 360 x 252 (bottom margin 54, plot height unchanged), tick labels sit just under the baseline, and ONE `layoutChartLabels` call places the field-note ratio labels (sounding or in the subset; `first` items, natural spot under their mark, a leader only when moved to a lane or sideways, from the mark's baseline end) and then the dip names (none within `NEAR_X` 4 units of a drawn note label; leader from the dot), all by lane together. `state/dipLabel.ts` is retired. Field notes NOT in the subset are solid marks at 0.35 opacity (no dash); in-subset, lit, selected and pinned marks are full strength.
- Lib: `src/lib/harmonic-field/liveRoughness.ts` (`liveRoughness`, `liveCurveStep`, `fieldMarks`). `liveRoughness` and its curve are built on `scoreRoughness` with no copied formula; `fieldMarks` takes each faint mark's pair roughness from `dissonanceAt` (lib `visual.ts`, the function the Dissonance curve also uses). The curve value at x equals `scoreRoughness([...chord Hz, tone at x]).score` (tested). Cost: 4.7 microseconds per tone per curve point, so the step is `liveCurveStep(n) = max(1, ceil(0.7 n))` cents (8 notes at 1 c measured 38 ms, at 6 c 6.5 ms).
- Tests: `liveRoughness.test.ts` (lib, scenarios a, b, c, f, g, and `fieldMarks`), `HarmonicFieldLab.roughness.test.tsx` (d, e, h and the five-visualizer load), `state/layout.test.ts`, `state/persist.test.ts`.

## Type scale (M8k)

Every font size in the lab CSS is one of eight custom properties, defined once on `:root` at the top of `components/lab.module.css` (on `:root`, not `.root`, so portalled menus and popovers inherit them): `--lab-fs-tiny` 0.6875rem (counts, details, tags, tiny segmented control via `--sc-font-size`), `--lab-fs-small` 0.75rem (secondary UI), `--lab-fs-body` 0.8125rem (panel body), `--lab-fs-title` 0.875rem (titles, values), `--lab-fs-glyph` 1rem (heat sign), `--lab-fs-display` 1.5rem (Live total); SVG text `--lab-svg-fs-small` 9px (ticks, small labels) and `--lab-svg-fs-label` 11px (main labels). Old literals map: 0.625 and 0.6875rem to tiny, 0.75 to small, 0.8125 to body, 0.875 and 0.9375rem to title, 8.5, 9 and 10px to svg-small, 11 and 12px to svg-label; `0.92em` on numerals stays. The inline sizes in `KeysPanel`/`RingStats` use `SVG_FS_LABEL`/`SVG_FS_SMALL` from `state/typeScale.ts` (same two numbers, still scaled by `label.scale`). Mantine `size` props and Mantine's own variables are untouched. `typeScale.test.ts` (node, reads the CSS) fails on any `font-size` literal other than `inherit`, `1em`, `0.92em` or a `var(--lab-...)`, and on any of the eight properties being defined twice.

## M8i Shape groups (`state/chordGroups.ts`, lib `shapeGroups.ts`, `ChordCard` `group`)

- **What merges.** Ratio chips and positional rows with the same template (ratio) or pattern (positional) and the same step list on different roots are ONE card. Identity key: template or pattern + the successive differences of the chord's pitches in cents rounded to 0.5 c (`stepKey`, `SHAPE_TOL_C`; a step on a rounding boundary may split a group). Chips found only at a raised tolerance (dashed) and CPS chords never group (their key is null: a group of one). `groupByShape(items, key)` keeps the order of first appearance. A group of one renders the normal card (no row, no count). Section counts still count chips, not groups.
- **The card.** The same `ChordCard`: ring of the representative, title as today (template name; positional pattern), subtitle just the template text (`4:5:6`) or the pattern (`2-2`), pitches line = the shape in cents above the root (`0.0, 400.0, 700.0 c`), steps line as usual, both taken from the group's FIRST member (so they do not change when the Sketch stepper moves); right stat = the first member's error (ratio) or `#rank · score` of the best-ranked member (positional). The expand control is an extra row at the bottom of the card (`.groupRow`, left-aligned): a Mantine `Button size="compact-xs" variant="default"` reading `12 roots` with the drop-down arrow (`rightSection`, the look of the Composites "Items" button), `aria-expanded`, `aria-label` `Show|Hide the 12 roots of <title>`. It is a sibling of the card's main button (no button in a button): `.chipWrap[data-grouped]` is the visual box (column flex, panel background, picked outline) and its inner card button is transparent. The stash `+` moves to the top right. Grouped cards are one row taller; the dynamic min-height rules are unchanged.
- **Behavior.** The representative is the member whose root is the Sketch stepper root (`sketch.rootDeg` wrapped), else the first member; hover/focus preview, hold 1/4/5, click (arm/pick), shift-click, `+` stash, `-` and right-click send all use the representative's own handlers (the grouped `Chip` / `PositionalRow` IS the representative's component with a `group` prop). `data-picked` is true when any member is the picked chord. Hold 1 on a grouped card therefore plays the representative's root (the stepper root), not the first root.
- **Expanded.** The per-root cards render below, nested one tree level deeper (`.nest` indent and hairline), each a normal card with its own root. State: `ui.folds` under `grp:` + two 32-bit FNV hashes of (kind + template/pattern + step key) (`groupFoldId`, at most 60 chars, cap 256 shared with the sections). Reversed semantics: a stored `grp:` id = EXPANDED (default collapsed); `sanitizeFolds` is unchanged. `useGroupExpanded` in `Fold.tsx`.
- **Collapse all | Expand all.** Collapse all stores the section ids only (no `grp:` id: every group closes). Expand all stores NO section id and every `grp:` id of a group that exists now (ratio groups from the chips shown, positional groups from each pattern that fits: `ratioGroupIds`, `positionalGroupIds`), so everything opens including the roots; groups beyond the 256 cap stay collapsed (sections hold no entries, so the cap is for groups only).
- **Switch.** `Group shapes` (Mantine Switch, `Tip` `groupShapes`) in the `.chordsFolds` row, left of Collapse all | Expand all; `ui.groupShapes` (optional boolean, default true, sanitized with `bool`, no write on mount, old data loads). Off = every per-root card as before M8i (and Expand all writes no group ids).
- **Header counts (M8i).** Grouping off: a folder header shows the bare number n of individual chords as before. Grouping on (`ui.groupShapes`): `n (m)` (e.g. `144 (12)`), m = the number of unique shapes once grouped (groups of one included, shown even when m equals n); the full sentence `n total chords here (m unique chords once shapes are grouped)` is the title and the accessible label (`GroupedCount` in `Fold.tsx`, `role="note"`). The count slot (`.foldCount`) has one fixed width in both states (`min-width: 8ch`, right-aligned, nowrap, tabular numerals from `Num`), so toggling the switch never shifts the header row. n and m come from the grouping function (`shapeCounts` in `state/chordGroups.ts`: found chips only; positional: `groupByShape` over the stacked chords of each pattern, no ranking). The CPS section has none. Each level (Ratio chords, size section, family row, Positional, pattern group) computes its own grouping (a group never crosses a template or a pattern, so the levels agree).
- **Clickable tree guides (M8i).** Every nested block that belongs to a folder (a size section, a Positional pattern group, a grouped card's roots) has a `NestGuide` (`Fold.tsx`): a transparent strip (`.nestGuide`, absolutely positioned, 0.375rem wide, inside the nest's left padding, so it never overlaps the cards, the scrollbar gutter or the stash buttons) over the 1px line. A click toggles the SAME state as the folder's header button (`useFold` id or `useGroupExpanded` id, so it is remembered and Collapse all | Expand all treat it alike). The line brightens (`--text-muted`) while the strip is hovered (`.nest:has(> .nestGuide:hover)`). The strip is `aria-hidden`, `tabIndex={-1}`, with a `Collapse <name>` / `Expand <name>` title; the header button stays the accessible control. The CPS Otonal / Utonal rows are not foldable and have no guide.
- **Chord card ring root marker**: `ChordDrawing` (`ShelfPanel.tsx`) takes an optional `rootCents`; `ChordCard` passes `ring.cents[0]` (a grouped card's ring is drawn from its representative, so the chevron follows that root). It draws the mode-root `ModeChevron` (`data-testid="chord-root"`, via the new `testId` and `strokeWidth` props) just outside the dot on the radial line, pointing in, sized by the `ROOT_TIP`/`ROOT_ARM`/`ROOT_STROKE` constants in `ShelfPanel.tsx` (tip just outside the dot edge, arms 0.17, stroke 0.0244 viewBox units); `.drawing` has `overflow: visible` so the ring box stays fixed. No chevron for an empty chord.
- **Small-ring reference (human, 2026-11-18): the Composites panel card ring is the basis for every small ring.** `CompositeRing` at 4.5rem (64-unit box at 72 px: ring radius 24 = 27 px, plain dot 2.6 = 2.9 px, outline `--grid` 1 unit = 1.125 px). `ChordDrawing` defaults to the same: `DRAWING_R` 0.75, `DRAWING_DOT_R` 0.08125 (exported from `ShelfPanel.tsx`), `.drawingRing` `--grid` at 1/32 unit; every chord card ring (wide and narrow, shelf slots) is 4.5rem (`--chord-card-ring(-narrow)`, `.drawing`). A ring drawn larger keeps the stroke widths (divide by `--drawing-k`, the size over 4.5rem) and sets its own dot size (`dotR`): the Product module's rings are 13.5rem (`--drawing-k: 3`) with dots 1.5x the card dot (`PRODUCT_DOT_R`). Its Result ring's marks are the composite family's (CompositeRing: common r 4, added r 4.5 with plus arms 2.2, in its 64-unit box) at the card's 1.125 px a unit, times 1.5: original = filled `--text-subtle`; new and merged are change ticks (below).
- **Change ticks (M8m, human, 2026-11-18): `components/ChangeTicks.tsx` is the one change mark for the big rings** (Product result ring, Keys big ring, `CompositeRing` `big` in the Send popup; small card rings keep their plain marks). One radial tick per changed note at the pitch's exact angle, every kind 14 px total (`TICK_LEN_PX`, screen px via `k` units per px), stroke 1.6875 px non-scaling, color by `data-kind` (`--mark-green/blue/red/orange`): added = outward with a 6 px cross bar 3 px from the tip (a plus); dropped = inward, plain; missing = inward, dashed 3/2 px, ending in a solid open circle r 2.5 px (line + o = 14 px); merged = across the ring line with a 6 px bar at both ends. Common/original notes stay plain dots; no stagger, no heads. Rings render the ticks before their labels so labels sit on top. (The earlier pinhead design was tried and dropped as cluttered.)

## Monzo paint performance (M8p)

- The painted monzo is LOCAL to the Relative picker while it is open (`components/useLocalMonzo.ts`, owned by `RelativeModal`). `latest` is the immediate truth (the matrix's gap fill, Ctrl line and snapshot logic, Add and Pin read it); `monzo` is what is drawn and sounded, updated at most once per animation frame (`requestAnimationFrame`; the Rows `-`/`+` buttons and Reset draw at once). A paint stroke renders only the picker: nothing outside it (main ring panel, workspace, stats, field table, tuner strip) re-renders.
- `state.relative.monzo` (runtime only) is written once, with `relative/monzoSet`, when the picker closes (unmount), so the next opening starts where the last one ended. It is the picker's opening value; nothing else reads it. Closing, switching tabs and a note vanishing all unmount the picker. Switching Rings / Near / Monzo or Matrix / Rows keeps the picker mounted and so the local value.
- The hold 1 / 4 / 5 preview target (`audio.setPreviewTarget`, key `rel:<source>:<landing>:<field>`) is set by `RelativeModal` itself (it used to be a `RingPanel` state, which re-rendered the whole ring panel per change). It reads the same `pointLanding` the ghost draws, in the same commit's effect, so sound and picture change together. In Monzo, `pointLanding` is a hovered pin card's landing, else the ghost (`mLanding`: the hover preview over the matrix or rows, otherwise the painted or Alt-shown landing), so holds 1 / 4 / 5 sound the ghost anywhere in the picker (M9f look 2; before, they were silent off the matrix).
- The page test `HarmonicFieldLab.monzoPerf.test.tsx` guards it: one stroke of 22 mouse events over 5 animation frames gives 5 picker renders and 0 renders outside it.
